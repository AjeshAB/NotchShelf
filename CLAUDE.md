# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

NotchShelf is a native macOS 26+ menu-bar app (`LSUIElement`, no Dock icon) that puts a file shelf and clipboard history in the MacBook notch. Swift/AppKit/SwiftUI/SwiftData, with KeyboardShortcuts and Sparkle as SwiftPM dependencies. Not sandboxed. The app lives in `NotchShelf/`; `website/` is a separate static marketing site (its own git repo, `website/dist`) and `build/` is generated output.

## Commands

`project.yml` (XcodeGen) is the source of truth — `NotchShelf.xcodeproj` is regenerated by the scripts, so edit `project.yml` (targets, deps, Info.plist properties), not the pbxproj. Requires `brew install xcodegen` and an Xcode with a macOS 26+ SDK.

```sh
./scripts/build.sh          # xcodegen + Debug build into build/, ad-hoc codesign
open build/Build/Products/Debug/NotchShelf.app
./scripts/test.sh           # xcodegen + XCTest (NotchShelfTests)
./scripts/package-local.sh  # build/NotchShelf-development.dmg
./scripts/release.sh        # archive/sign/notarize/staple DMG; needs TEAM_ID, SIGN_IDENTITY, NOTARY_PROFILE, SPARKLE_FEED_URL, SPARKLE_PUBLIC_KEY
./scripts/profile-idle.sh   # sample idle CPU/memory
```

Single test: run `xcodebuild` as in `scripts/test.sh` with `-only-testing:NotchShelfTests/<Class>/<testName>`. Tests live in `NotchShelfTests/StoreTests.swift`; they use an in-memory SwiftData container, isolated pasteboards and temp directories. There is no linter. Manual hardware/permission checks are in `docs/QA.md`; perf notes in `docs/Performance.md`.

## Architecture

`AppCoordinator` (`App/`) is the hub: it owns `Preferences`, `ShelfStore`, `ClipboardStore`, `DragWatcher`, the SwiftData `ModelContainer` (`~/Library/Application Support/NotchShelf/Clipboard.store`), and the registered global shortcut (⌥⌘V default). Views get it via `@EnvironmentObject`. It opens the DB at init and deliberately `fatalError`s rather than erasing a store that fails to open.

- **Window/**: `rebuildPanels()` creates one `NotchWindowController` (fixed-size nonactivating panel) per built-in display, falling back to one panel on the primary screen for external-only setups; it rebuilds on `didChangeScreenParametersNotification`. Each panel has a `NotchViewModel` (open/collapse/peek state, `.shelf` vs clipboard tab). The panel's max frame is fixed and only the black silhouette animates; click-through relies on tracking areas and pointer monitoring, so transparent areas must not swallow clicks.
- **Services/**: `ShelfStore` persists shelf entries as file bookmarks (originals) or managed copies in `Shelf/` (raw drops/temp files); removing an entry never deletes files. `ClipboardStore` polls `NSPasteboard` every 0.5s only when enabled (off by default), filters concealed/transient/auto-generated markers and excluded frontmost-app bundle IDs, dedupes by content hash (keeping pin state), enforces size caps and age/count retention (pins exempt), and ignores its own writes. `DragWatcher` detects global drags to reveal the shelf peek.
- **Models/**: `Preferences` (settings), `ClipboardEntry` (SwiftData, external binary storage).
- **Views/**: `NotchRootView` hosts the Files/Clipboard tabs; `ShelfView` is the grid with an AppKit multi-file drag source; `ClipboardView` is search/pin/keyboard selection; `SettingsView`.
- Pasting: the coordinator remembers the previous frontmost app; with Accessibility granted it reactivates that app and pastes, otherwise it just copies for manual ⌘V.

Adding shelf items is drag-and-drop only by design (no file picker, toolbar, or footer). Reduce Motion disables the spring and hover fade. Sparkle only starts when a real feed URL and public key are in Info.plist (injected by `release.sh`).
